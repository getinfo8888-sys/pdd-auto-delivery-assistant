# 开发说明

## 结构

- `src/core`：规则匹配、任务持久化、重试、启动恢复和网络刷新。
- `src/platform`：官方商家页面的读取、消息发送、回执与订单 / 售后适配。
- `src/renderer`：本地界面、表单和内嵌页面布局。
- `src/main.cjs`：Electron 窗口、内嵌视图、调度、IPC 和系统托盘。
- `test`：无真实平台写入的单元测试；`scripts`：隔离工作流与开发诊断。

业务成功依赖平台明确回执。自动答复使用持久化正文，保留官方发送、回执消费和会话状态更新流程；仅对绑定本次请求的底层消息传输做适配。不直接修改接待列表的等待状态，不伪造平台成功结果。

店铺页面使用固定在可用区域内的原生视图，容器尺寸、滚动和窗口变化会同步布局。尺寸无效时移除视图，避免旧位置遮挡其他内容；切换到其他页面或打开弹窗时隐藏原生页面。

## 验证

```powershell
npm test
npx electron . --smoke-test
npx electron . --startup-smoke
npx electron . --capability-smoke
npx electron scripts/popup-smoke.cjs
npx electron . --layout-smoke
npx electron . --shared-rules-smoke

```

这些冒烟使用隔离数据和平台替身，布局测试的客服 / 订单页使用本地 data URL，不连接真实商家。开发诊断写到 Git 忽略的 `work` 目录。

### 正式版与测试版

后续新功能先在独立测试版开发和验证，正式版持续接待。测试版构建必须分开安装目录、appId、实例锁、规则与任务目录、浏览器会话以及提醒凭据；不能把仅换名称、仍共用正式版数据的程序当作独立测试版。现有隔离冒烟入口用于平台样本验证，不能用普通 `npm start` 代替隔离测试，因为普通启动沿用正式版兼容数据目录。

测试期间不要登录正式版正在接待的店铺，避免平台互踢。开发、打包、验证均保持正式版运行；只有待发布构建已经验证并打包完成、正式任务空闲且完整备份与旧版回退文件已准备好时，才安排正式版切换。切换后核对规则、任务记录、官方连接和实际监听状态，确认恢复接待后再继续其他维护。

执行 `npm run preview:ui` 打开独立的界面测试窗口。它使用 `local.linkfulfillment.workbench.ui-preview` 身份和 `work/ui-preview` 内的数据、浏览器目录，禁止 HTTP、HTTPS 和 WebSocket 外部连接，不读取正式版规则、会话或密钥，也不修改系统开机启动。窗口明确标注“界面测试版”，可试用导航与表单；平台操作、图片上传及手机推送仅在正式版提供。此入口不代替上面的真实主进程隔离冒烟。预览期间正式版继续运行，关闭预览不会退出正式版。

设置分类入口：

| 一级页面 | 二级标签 | 内容 |
| --- | --- | --- |
| 助手设置 | 本机运行（默认） | 自动监听、开机启动、托盘、全局发送上限 |
| 助手设置 | 备份与迁移 / 连接与版本 / 异常提醒 | 规则备份、分类迁移、连接检查和桌面 / 手机通知 |
| 发货内容 | 发货内容列表（默认） / 发货设置 | 商品规则、默认发货、尾缀、链接、自动发货与确认 |
| 智能答复 | 答复内容（默认） / 答复策略 / 待回复保障 | 欢迎语与关键词、延迟与人工介入、补答和重试 |
| 自动退款 | 当前页面 | 自动同意开关、处理说明和记录 |

分类仅改变入口，沿用既有字段。纯链接开关仍由答复和发货共用，两处均明确说明；全局发送上限影响两类消息，保留在本机运行。业务设置统一通过现有 `settings:update` 保存；提醒独立保存。分类导航先校验、保存业务草稿，无效数值阻止离开当前标签；仅浏览不触发保存或暂停。提醒草稿跨标签保留，只有点击提醒保存按钮才提交，不混入业务设置保存。

`src/core/shared-content.cjs` 定义 `local-commerce-content` 第 2 版分类文字交换格式，`scope` 仅为 `replies` 或 `delivery`。新文件只包含对应类别的字段；继续读取第 1 版合并文件及旧规则备份，按导入入口筛选类别。合并 / 替换均不触碰另一类别的内容与图片，系统规则保留。主进程保存导入草稿；确认时校验本机配置未变化、监听和平台操作已空闲，先备份再更新。会话、回执、任务、店铺绑定与平台执行设置不进入交换文件。`--shared-rules-smoke` 使用本地文件和对话框替身验证分类导出、预览、取消、运行保护、备份与实际导入，不发起平台写入。

淘宝助手使用独立项目、进程、appId 和本地数据目录，不在本应用中加入淘宝页面或任务分支。可复用纯文本规则格式与已经验证的匹配处理方式；两端的账号、传输、真实回执和订单去重由各自平台实现和验证。

执行 `npm run dist` 构建 Windows x64 的 NSIS 安装包，执行 `npm run dist:portable` 构建便携程序。安装包为简体中文安装向导，可选择安装目录，默认当前用户安装，创建桌面和开始菜单快捷方式，并注册系统卸载入口；卸载默认保留用户数据。安装包已包含 Electron 运行环境，最终使用者无需 Node.js。

二进制只包含 `src` 与 `package.json`。不要把 `work`、浏览器缓存、本机账号数据、证据文件或实际客户截图加入源码分发。

当前构建未配置 Windows 代码签名证书，安装包未签名；对外正式发布时可另外配置发布者证书。

应用内部数据目录和 appId 沿用早期版本以兼容升级；界面、窗口、托盘和便携包统一使用“拼多多自动发货助手”名称。

## 字体与颜色规范

参考 [Ant Design 字体规范](https://ant.design/docs/spec/font/) 的正文基准、字号层级和克制字重，以及 [WCAG 1.4.3](https://www.w3.org/WAI/WCAG21/Understanding/contrast-minimum.html) 的文字对比度要求。下面是本应用选定的角色映射，集中定义在 `src/renderer/design-tokens.css`，不是对某个设计系统整套组件的照搬。

| 用途 | 字号 / 行高 | 字重与颜色 |
| --- | --- | --- |
| 页面标题 | 24 / 32px | 600，主要文字色 |
| 弹窗标题、欢迎区标题 | 20 / 28px | 600，主要文字色 |
| 侧边导航、选项卡 | 16 / 24px | 未选中 500 深色；选中 600 主题色、底色与下划线 |
| 功能名称、表单、按钮、正文、分组标题 | 14 / 22px | 400 或 500；分组标题使用次要文字色，避免抢过导航 |
| 说明、元信息、状态标签 | 12 / 20px | 常规字重，保留足够对比度的灰色或语义状态色 |

统计数字单独使用 32px 展示字号，不扩散到普通内容。主要文字 `#1f2937`，次要文字 `#475569`，说明 `#5f6f82`，主题色 `#0f6b75`。浅灰 `#94a3b8` 仅用于真正禁用的控件；未选中导航仍是可用功能，不能当作禁用状态。成功、等待和异常标签使用各自的语义色。可读文字以实际背景上的至少 4.5:1 为验证目标，不把界面截图或第三方官方页面当作全应用无障碍认证。

`--layout-smoke` 同时运行 `scripts/typography-smoke.cjs`，读取实际渲染后的字号、字重和前景 / 背景色，计算代表性角色与状态标签的对比度，并检查三种窗口尺寸的导航边界。图像和详细结果保存在忽略目录 `work/typography`。新增界面复用现有角色，避免继续添加零散字号和过浅文字色；官方内嵌页面保留其自身样式。

## 异常提醒

`alert-health.cjs` 只观察已有客服、订单、售后与自动恢复状态，不添加平台轮询。`alert-monitor.cjs` 负责持续时间、独立失败标识计数、启动保护、稳定恢复、客服故障升级及通知去重。手动暂停取消本次未提交通知；短暂恢复不重置同一次故障。

`alert-service.cjs` 将提醒配置、Windows safeStorage 加密后的密钥与通知发件箱独立保存在本机 `phone-alerts.json`，不进入 Engine 配置或规则导出。发送前保存提交意图，只有推送服务提供受理回执才标记 accepted，不把服务受理当作手机送达；最多三次退避尝试，重启仍保留次数和去重记录。传输只访问固定 HTTPS 服务，错误与日志不记录密钥或客户内容。

`desktop-alert.cjs` 创建独立的本地提示窗口，按显示器工作区停靠右下角，用 showInactive 避免抢焦点；默认不依赖手机凭据或网络。预加载仅允许“打开助手”和“收起”，主进程校验确切窗口与主框架。用户收起不修改业务状态，同一次故障不重开；稳定恢复或手动暂停后销毁提示。桌面验证脚本使用独立窗口和数据目录，校验实际显示、焦点与打开按钮，不连接商家或推送服务。

整机断网、休眠或应用退出无法靠本进程即时发送手机通知，外部心跳尚未接入。提醒模块异常仅显示和记录提醒故障，不阻断业务恢复。

## 图标

图标底色参考[拼多多官网标识](https://cdn.pinduoduo.com/upload/home/img/common/pdd_logo_v2.png)，使用 `#E02E24` 纯红色，中央为放大的白色“拼”字。文字已转为矢量轮廓，显示不依赖系统字体；可编辑源文件是 `src/renderer/icon.svg`。修改后执行 `npm run make-icon`，使用已有 Electron 运行环境生成窗口 PNG、托盘 PNG，以及包含 16 / 20 / 24 / 32 / 48 / 64 / 128 / 256 像素的 Windows ICO。安装程序把同一 ICO 用于桌面和开始菜单快捷方式。维护升级可使用 `--start-paused` 打开软件，保留升级前的暂停状态，不修改自动监听设置。

订单和售后通过独立的非重入检查与退避状态运行，订单请求超时不会占用客服轮询。任务派发按依赖能力筛选，仍需验证订单、身份与真实回执。网络恢复保留验证码、草稿和隐藏订单页，刷新可见页面或失效的客服连接。功能隔离冒烟覆盖验证中答复、慢订单请求、退款独立运行、恢复后续发及缺失买家编号查询。

客服弹窗守卫第二版补充官方通知模态框（含 span.cancel）和已识别的功能介绍弹窗；按语义匹配关闭控件，优先调用官方当天不再提示的事件。DOM 观察处理延迟出现的提示，关闭失效后退避重试，不因前三次失败永久放弃。只在官方客服页处理已识别的可选提示。
