# 开发说明

## 结构

- `src/core`：规则匹配、任务持久化、重试、启动恢复和网络刷新。
- `src/platform`：官方商家页面的读取、消息发送、回执与订单 / 售后适配。
- `src/renderer`：本地界面、表单和内嵌页面布局。
- `src/main.cjs`：Electron 窗口、内嵌视图、调度、IPC 和系统托盘。
- `test`：无真实平台写入的单元测试；`scripts`：隔离工作流与开发诊断。

业务成功依赖平台明确回执。自动答复使用持久化正文，保留官方发送、回执消费和会话状态更新流程；仅对绑定本次请求的底层消息传输做适配。不直接修改接待列表的等待状态，不伪造平台成功结果。

店铺页面使用固定在可用区域内的原生视图，容器尺寸、滚动和窗口变化会同步布局。尺寸无效时移除视图，避免旧位置遮挡其他内容；切换到其他页面或打开弹窗时隐藏原生页面。

### 正式版与测试版

后续新功能先在独立测试版开发和验证，正式版持续接待。测试版构建必须分开安装目录、appId、实例锁、规则与任务目录、浏览器会话以及提醒凭据；不能把仅换名称、仍共用正式版数据的程序当作独立测试版。现有隔离冒烟入口用于平台样本验证，不能用普通 `npm start` 代替隔离测试，因为普通启动沿用正式版兼容数据目录。

测试期间不要登录正式版正在接待的店铺，避免平台互踢。开发、打包、验证均保持正式版运行；只有待发布构建已经验证并打包完成、正式任务空闲且完整备份与旧版回退文件已准备好时，才安排正式版切换。切换后核对规则、任务记录、官方连接和实际监听状态，确认恢复接待后再继续其他维护。

更新前先核对正在运行的软件实际载入的规则与设置，在任务空闲时保存当下快照，退出后补齐完整备份并核对文件指纹。正常升级只替换程序文件，保留现有数据；不能自动拿昨天或其他历史快照覆盖当前配置。只有用户明确要求恢复某份历史备份时才进行恢复，并先保全当前数据。

Windows 的 MSIX / 打包宿主可能给子进程继承 AppData 重定向。同一个目录字符串在维护工具和用户日常启动的软件中，可能对应不同文件；一份副本包含旧规则，并不表示当前规则已被删除。遇到差异时先分别保全、比对，不自动同步或覆盖。正式版应通过用户正常的桌面入口打开，启动后核对实际页面里的规则名称、最新新增内容、设置指纹、任务记录和实际文件写入位置；仅检查磁盘文件中的数量、安装版本或连接状态不足以证明新进程使用了最新数据。

执行 `npm run preview:ui` 打开独立的界面测试窗口。它使用 `local.linkfulfillment.workbench.ui-preview` 身份和 `work/ui-preview` 内的数据、浏览器目录，禁止 HTTP、HTTPS 和 WebSocket 外部连接，不读取正式版规则、会话或密钥，也不修改系统开机启动。窗口明确标注“界面测试版”，可试用导航与表单；平台操作、图片上传及手机推送仅在正式版提供。此入口不代替上面的真实主进程隔离冒烟。预览期间正式版继续运行，关闭预览不会退出正式版。

设置分类入口：

| 一级页面 | 二级标签 | 内容 |
| --- | --- | --- |
| 助手设置 | 本机运行（默认） | 自动监听、开机启动、托盘、全局发送上限 |
| 助手设置 | 备份与迁移 / 连接与版本 / 异常提醒 | 规则备份、分类迁移、连接检查和桌面 / 手机通知 |
| 发货内容 | 发货内容列表（默认） / 发货设置 | 商品规则、默认发货、尾缀、链接、自动发货与确认 |
| 智能答复 | 答复内容（默认） / 答复策略 | 欢迎语与关键词、延迟与人工介入；补答和重试内置启用 |
| 自动退款 | 当前页面 | 自动同意开关、处理说明和记录 |

分类仅改变入口，沿用既有字段。纯链接开关仍由答复和发货共用，两处均明确说明；全局发送上限影响两类消息，保留在本机运行。业务设置统一通过现有 `settings:update` 保存；提醒独立保存。分类导航先校验、保存业务草稿，无效数值阻止离开当前标签；仅浏览不触发保存或暂停。提醒草稿跨标签保留，只有点击提醒保存按钮才提交，不混入业务设置保存。

默认页面为店铺工作台的客服页。普通 `settings:update` / `config:update` 保留主进程当前 `running`，不会调用暂停或重启监听；关闭某项自动功能只通过对应任务门控生效，全部关闭时也可被动监听。导入整份规则仍须用户先手动暂停并等待平台操作完成，文件对话框返回后再次核验。

旧字段 `catchUpUnrepliedEnabled` 与 `replyBodySpaceRetryEnabled` 继续兼容读取，统一归一为 true，界面不再暴露保障开关；实际补答仍受总监听与 `autoReplyEnabled` 限制。普通设置不再有立即保存按钮。未提交的排队答复保存咨询原文，规则变化时重新匹配当前内容，延迟以原任务建立时间计算，冷却按原正文和成功回执计算。配置写入后使在途预检查的写入版本失效，确认尚未提交时才刷新待发任务；已成功或结果不明的原文、发送参数和回执保持原样。`--smoke-test` 的 live-settings 样本覆盖真实 IPC 保存、预检查竞态、独立开关和手动暂停保持，不连接真实平台。

待回复扫描不再仅按文字类型筛选。买家撤回、图片、商品卡或未知消息类型，只要官方仍有有效待回复时间、参与者身份一致且只读历史包含对应标记，就以当前默认答复安排补答；不读取已撤回正文来匹配关键词。内部 `official-pending:` 来源键包含官方标记编号和待回复起始时间，用于同一轮扫描及重启后的去重，不作为平台发送回执。新的待回复周期可以再次处理，已有成功或结果不明的同轮发送不重复提交。默认答复为空时不编造文案，需要先配置默认答复。

发送前继续核验官方最新状态，人工已回复或待回复标记已清除则停止旧补答。最新非文字消息缺少待回复时间时，分页复查官方待回复列表，不能把字段缺失直接当成已回复。单个会话核验失败不会吞掉同页其他会话；失败摘要进入诊断记录，并在30秒后继续复核。用 `electron scripts/ui-preview.cjs --pending-reply-demo` 打开独立的保障测试版，使用单独身份、实例锁、数据及浏览器目录，阻断外网；按钮仅通过隔离样本回执验证默认补答和重复扫描去重，不能证明真实买家已收到消息。

`src/core/shared-content.cjs` 定义 `local-commerce-content` 第 2 版分类文字交换格式，`scope` 仅为 `replies` 或 `delivery`。新文件只包含对应类别的字段；继续读取第 1 版合并文件及旧规则备份，按导入入口筛选类别。合并 / 替换均不触碰另一类别的内容与图片，系统规则保留。主进程保存导入草稿；确认时校验本机配置未变化、监听和平台操作已空闲，先备份再更新。会话、回执、任务、店铺绑定与平台执行设置不进入交换文件。`--shared-rules-smoke` 使用本地文件和对话框替身验证分类导出、预览、取消、运行保护、备份与实际导入，不发起平台写入。

淘宝助手使用独立项目、进程、appId 和本地数据目录，不在本应用中加入淘宝页面或任务分支。可复用纯文本规则格式与已经验证的匹配处理方式；两端的账号、传输、真实回执和订单去重由各自平台实现和验证。

执行 `npm run dist` 构建 Windows x64 的 NSIS 安装包，执行 `npm run dist:portable` 构建便携程序。安装包为简体中文安装向导，可选择安装目录，默认当前用户安装，创建桌面和开始菜单快捷方式，并注册系统卸载入口；卸载默认保留用户数据。安装包已包含 Electron 运行环境，最终使用者无需 Node.js。

二进制只包含 `src` 与 `package.json`。不要把 `work`、浏览器缓存、本机账号数据、证据文件或实际客户截图加入源码分发。

当前构建未配置 Windows 代码签名证书，安装包未签名；对外正式发布时可另外配置发布者证书。

应用内部数据目录和 appId 沿用早期版本以兼容升级；界面、窗口、托盘和便携包统一使用“拼多多自动发货助手”名称。

## 字体与颜色规范

参考 [Ant Design 字体规范](https://ant.design/docs/spec/font/) 的正文基准、字号层级和克制字重，以及 [WCAG 1.4.3](https://www.w3.org/WAI/WCAG21/Understanding/contrast-minimum.html) 的文字对比度要求。下面是本应用选定的角色映射，集中定义在 `src/renderer/design-tokens.css`，不是对某个设计系统整套组件的照搬。

| 用途 | 字号 / 行高 | 字重与颜色 |
| --- | --- | --- |
| 页面标题 | 24 / 32px | 600，主要文字色 |
| 弹窗标题、欢迎区标题 | 20 / 28px | 600，主要文字色 |
| 侧边导航、选项卡 | 16 / 24px | 未选中 500 深色；选中 600 主题色、底色与下划线 |
| 功能名称、表单、按钮、正文、分组标题 | 14 / 22px | 400 或 500；分组标题使用次要文字色，避免抢过导航 |
| 说明、元信息、状态标签 | 12 / 20px | 常规字重，保留足够对比度的灰色或语义状态色 |

统计数字单独使用 32px 展示字号，不扩散到普通内容。主要文字 `#1f2937`，次要文字 `#475569`，说明 `#5f6f82`，主题色 `#0f6b75`。浅灰 `#94a3b8` 仅用于真正禁用的控件；未选中导航仍是可用功能，不能当作禁用状态。成功、等待和异常标签使用各自的语义色。可读文字以实际背景上的至少 4.5:1 为验证目标，不把界面截图或第三方官方页面当作全应用无障碍认证。

`--layout-smoke` 同时运行 `scripts/typography-smoke.cjs`，读取实际渲染后的字号、字重和前景 / 背景色，计算代表性角色与状态标签的对比度，并检查三种窗口尺寸的导航边界。图像和详细结果保存在忽略目录 `work/typography`。新增界面复用现有角色，避免继续添加零散字号和过浅文字色；官方内嵌页面保留其自身样式。

## 异常提醒

`alert-health.cjs` 只观察已有客服、订单、售后与自动恢复状态，不添加平台轮询。`alert-monitor.cjs` 负责持续时间、独立失败标识计数、启动保护、稳定恢复、客服故障升级及通知去重。手动暂停取消本次未提交通知；短暂恢复不重置同一次故障。

`alert-service.cjs` 将提醒配置、Windows safeStorage 加密后的密钥与通知发件箱独立保存在本机 `phone-alerts.json`，不进入 Engine 配置或规则导出。发送前保存提交意图，只有推送服务提供受理回执才标记 accepted，不把服务受理当作手机送达；最多三次退避尝试，重启仍保留次数和去重记录。传输只访问固定 HTTPS 服务，错误与日志不记录密钥或客户内容。

`desktop-alert.cjs` 创建独立的本地提示窗口，按显示器工作区停靠右下角，用 showInactive 避免抢焦点；默认不依赖手机凭据或网络。预加载仅允许“打开助手”和“收起”，主进程校验确切窗口与主框架。用户收起不修改业务状态，同一次故障不重开；稳定恢复或手动暂停后销毁提示。桌面验证脚本使用独立窗口和数据目录，校验实际显示、焦点与打开按钮，不连接商家或推送服务。

整机断网、休眠或应用退出无法靠本进程即时发送手机通知。从0.3.17起提供可选云端监护，须配置自己账号的服务；安装包不包含部署凭据或预设的监护地址。提醒模块异常仅显示和记录提醒故障，不阻断业务恢复。

### 云端监护

`src/core/cloud-watchdog.cjs` 每15秒提交一次由现有 `connectionSample` 得出的运行状态，不增加拼多多接口请求，不发送客户、订单、店铺或登录资料。心跳采用独立随机密钥，通过 HTTPS 请求头鉴权，本机使用 safeStorage 单独保存，规则导出不含监护凭据。每次进程启动生成独立运行标识并递增序号；云端拒绝重复序号、过期时间戳和额外字段。账号内一份部署只监护一个实例，不让测试版与正式版共用同一个监护对象或心跳凭据。

首次接入时，从正常桌面入口启动目标安装，在该程序的“助手设置 → 异常提醒 → 云端离线监护”中保存心跳密钥。safeStorage 加密内容依赖目标程序实际使用的用户数据与系统加密上下文；不要把临时工具或另一份应用配置生成的密文复制给正式版。普通更新保留已有监护配置，无须重新初始化。配置完成须核对界面已确认心跳、云端监护已布防，以及监听和原有规则仍正常，不能仅凭配置文件存在判定接入成功。

`scripts/cloud-watchdog/worker.mjs` 使用 SQLite Durable Object 和持久化 Alarm。最后一次心跳超过60秒，或持续报告异常超过60秒时尝试推送；短暂恢复不重置同一故障，正常并稳定60秒后重新布防。只有包含推送编号的 Server酱 回执才标记 accepted；明确拒绝最多退避尝试三次，结果不明则保留 uncertain，不盲目重发。发送前持久化 submitting；重复执行或提交后重启不会重复发送。云端保存最近一次推送状态，主动暂停不会擦除该回执。单份部署每天至多尝试五次，避免故障风暴；这不等于绕过推送服务自己的账号总额度。

客户端在拿到云端已配置推送渠道的心跳回执前保留原有本机手机提醒。确认后由云端负责手机故障提醒，本机桌面提示继续工作，避免两个通道同时重复提交。普通设置保存仍保留监听状态；关闭监护要求先由用户手动暂停监听，再取得云端暂停回执。运行、异常与暂停状态切换时优先提交，不额外等满15秒。直接关机、退出或程序崩溃不自动解除云端监护。维护前应主动暂停并确认，断网时无法提交的暂停不能显示成已完成。本机 `cloud-watchdog.jsonl` 记录状态变化和 HTTP 状态码，不记录密钥、客户资料、响应正文或每条正常心跳。

开发者部署时使用自己的免费 Cloudflare 账号与 Workers Free，配置文件是 `scripts/cloud-watchdog/wrangler.jsonc`。通过官方 Wrangler 授权后部署，依次配置三个 Worker Secrets：`HEARTBEAT_TOKEN`（32位以上随机心跳密钥）、`ADMIN_TOKEN`（另一份随机管理密钥）、`SERVERCHAN_SENDKEY`（本人授权上传的推送密钥）。管理密钥不放进助手界面。禁止把真实密钥写入配置文件、环境示例、Git、URL 查询参数或日志；关闭 Worker 的请求日志与跟踪采样。当前配置不申请付费套餐，免费额度耗尽会使监护不可用，不能宣称免费服务有严格的一分钟送达保证。

注意 Workers 的 `fetch` 不支持 `redirect: 'error'`。云端传输使用 `manual` 并拒绝3xx，防止密钥随重定向发往其他地址；本机 Electron 的传输保留自己的实现。依据：[Cloudflare Request 文档](https://developers.cloudflare.com/workers/runtime-apis/request/)、[Durable Objects Alarms](https://developers.cloudflare.com/durable-objects/api/alarms/)、[免费额度](https://developers.cloudflare.com/durable-objects/platform/pricing/)。

验证入口：`npm test`；`electron . --cloud-watchdog-smoke` 验证真实主进程 IPC、健康采样、独立开关和通知归属，全部使用隔离平台与假云端；`node scripts/cloud-watchdog-runtime-smoke.cjs` 使用本地 Wrangler 所带 Miniflare / workerd 验证 Worker 请求兼容性，拦截全部推送请求，不向真实服务发送。后者默认从忽略目录 `work/cloudflare-tools/node_modules/miniflare` 加载，也可把依赖绝对路径作为参数传入。

`electron scripts/cloud-watchdog-preview.cjs` 打开独立的监护测试窗口，使用单独 appId、实例锁、数据与浏览器会话。`--provision-test` 仅供本机维护，从忽略目录的测试部署清单与测试密钥初始化；`--test-loss` 须取得用户对其微信的一次测试授权后使用。它只停止测试心跳，不关闭真实网络；完成后必须取得云端暂停回执。测试文件、回执、密钥和截图都留在 `work/`，不提交。Windows 主机对 workers.dev 的直连稳定性和正常 Electron 网络路径都需要实测，不能仅凭部署成功就覆盖安装正式版。

测试按钮由 `scripts/cloud-watchdog/preview-controller.cjs` 管理。从暂停直接点击模拟断网时，先发送正常心跳并验证云端已开始监护；失败时不进入离线模拟、不显示假倒计时。收到确认后停止测试心跳。只读 `/v1/state` 使用心跳密钥查看精简状态，不修改最后心跳、监护开关、故障或 Alarm；模拟断网期间仍能显示倒计时与本次推送结果。旧的 accepted 记录不能充当本次成功，重复点击不能重置倒计时或绕过同一故障去重。已有上一轮异常时先恢复正常并稳定一分钟，或由用户主动暂停结束该轮，再开始新测试。

## 图标

图标底色参考[拼多多官网标识](https://cdn.pinduoduo.com/upload/home/img/common/pdd_logo_v2.png)，使用 `#E02E24` 纯红色，中央为放大的白色“拼”字。文字已转为矢量轮廓，显示不依赖系统字体；可编辑源文件是 `src/renderer/icon.svg`。修改后执行 `npm run make-icon`，使用已有 Electron 运行环境生成窗口 PNG、托盘 PNG，以及包含 16 / 20 / 24 / 32 / 48 / 64 / 128 / 256 像素的 Windows ICO。安装程序把同一 ICO 用于桌面和开始菜单快捷方式。维护升级可使用 `--start-paused` 打开软件，保留升级前的暂停状态，不修改自动监听设置。

订单和售后通过独立的非重入检查与退避状态运行，订单请求超时不会占用客服轮询。任务派发按依赖能力筛选，仍需验证订单、身份与真实回执。网络恢复保留验证码、草稿和隐藏订单页，刷新可见页面或失效的客服连接。功能隔离冒烟覆盖验证中答复、慢订单请求、退款独立运行、恢复后续发及缺失买家编号查询。
