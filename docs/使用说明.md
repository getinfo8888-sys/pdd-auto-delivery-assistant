# 拼多多自动发货助手使用说明

**[点这里下载安装包，下载完成后双击安装](https://github.com/getinfo8888-sys/pdd-auto-delivery-assistant/releases/download/v0.3.16/PDD-Auto-Delivery-Assistant-Setup-0.3.16-x64.exe)**

这是可以直接安装的 Windows 软件，不需要懂开发、安装 Node.js 或下载源码。

## 安装和打开

1. 点击上面的下载链接，保存文件名带 **Setup** 的安装包，然后双击打开。
2. 保持默认的“仅为我安装”，点击下一步；选择安装目录后点击“安装”。
3. 安装完成后点击“完成”，即可运行软件。以后双击桌面的“拼多多自动发货助手”快捷方式打开，也可从开始菜单打开。

安装包已包含全部运行环境，无需安装 Node.js 或解压源码 ZIP。源码包供开发者使用。适用于 Windows 10 / 11 的 64 位电脑。

更新前从系统托盘菜单选择“退出”，然后运行新版安装包。已有规则、任务记录和登录会话沿用本机数据。可在 Windows“设置 → 应用 → 已安装的应用”中卸载；默认保留本地规则和登录数据，重新安装后仍可继续使用。

## 配置和启动

软件默认打开“店铺工作台 → 客服页面”，由本人在官方页面完成商家登录，方便直接查看咨询和待回复会话。进入“发货内容”添加规则；名称用于自己识别，关键词用于匹配商品名称或 SKU，正文填写实际发送给买家的完整内容。多个关键词按“或”匹配，具体内容发生冲突时保留待处理。

可分别设置未匹配默认发货、统一尾缀、欢迎语、关键词答复和未匹配默认答复。它们的用途相互独立。每条内容均可附加图片 / 二维码，最多 5 张、每张 5 MB。图片需在对应店铺登录后上传。

在“智能答复 → 答复策略”开启智能答复，在“发货内容 → 发货设置”开启自动发货与确认发货，在“自动退款”页面开启退款处理。新安装的自动答复、自动发货、自动退款默认关闭，不预置任何商品规则。设置更改自动保存，监听保持原来的运行或暂停状态，无需再次开始监听。关闭智能答复只停答复；自动发货、确认发货和退款按各自开关运行。所有自动功能关闭时也可保持监听。需要暂停全部自动处理时，手动点击顶部“暂停监听”。

## 按分类查找设置

| 页面 | 默认显示 | 其他标签与设置 |
| --- | --- | --- |
| 助手设置 | 本机运行 | 备份与迁移、连接与版本、异常提醒；提醒放在最后 |
| 发货内容 | 发货内容列表 | 发货设置：自动发货、未匹配默认发货、统一尾缀、单独发送纯链接、自动确认发货 |
| 智能答复 | 答复内容 | 答复策略：欢迎语开关、延迟、冷却与人工介入；补答和失败重试为内置保障 |
| 自动退款 | 自动退款开关与记录 | 在当前页面设置，无需进入助手设置 |

欢迎语、默认答复和关键词正文在“智能答复 → 答复内容”编辑。每分钟发送上限由答复和发货消息共用，在“助手设置 → 本机运行”设置。单独发送纯链接也由答复和发货共用，两处开关保持一致。

业务设置更改自动保存，不再提供额外的“立即保存”按钮；切换标签前会校验并保存。填写无效数值时会留在原标签，继续使用上一份有效设置，监听不中断。等待中的答复会采用最新文案、延迟与冷却设置，发送前再次检查是否已经人工回复；已经提交平台的操作先按真实回执确认。异常提醒使用自己的“保存提醒设置”按钮，切换标签会保留尚未保存的草稿，保存提醒不会暂停监听。

## 回复、发货与退款

智能答复支持首次欢迎语、完全相等、通配符、包含关键词、表达式和默认答复。可配置延迟、冷却与人工接手策略。启动及运行中的待回复检查、明确拒绝后的重试是内置保障，随智能答复启用，无需另外打开补答开关；关闭智能答复时不发送补答。未取得明确结果的消息先核验，不能盲目重发。发送取得成功回执后，经官方页面自身的回执处理更新会话和接待列表。出现新咨询时仍按最新咨询判断，不强行清空等待状态。

“欢迎语延迟”控制首次欢迎的速度。“一般答复延迟”是收到咨询后关键词 / 默认答复的等待时间，规则填写了独立延迟时优先用规则值；开启人工接手后，等待期间检测到较晚的人工回复会取消待发答复。手机上尚未发出的输入内容无法可靠检测。

“相同正文冷却”是同一买家两次相同原文之间的最短发送间隔，从上一条取得成功回执开始计算；随机字符、时间尾缀不参与比较。它不是每次收到新咨询后的固定等待时间。希望先快速欢迎、后续留时间人工处理，可将欢迎语延迟设为 0，一般答复延迟设为 20 秒，并开启人工答复时停止待发自动答复。

拼多多官方自动回复不计为人工接手。如果官方仍将会话列为待回复，程序会核对近期消息，找回机器人回复前的买家咨询，按你的规则补答。历史版本因此误取消的未发送答复也会重新核验、安排补答。发送前发现有新的人工回复或买家咨询时，仍以最新会话为准；核验失败会保留重试，不直接当成已答复。

商品标题或 SKU 匹配关键词后发送对应内容；均未匹配时使用单独开启的默认发货内容。启用“正文后单独发送纯链接”后，按正文、各纯链接、各图片顺序发送，全部成功后才确认发货。链接保持原样，手机端能否直接点击由拼多多决定。

发送和确认发货失败会自动重试；结果不明先查询平台记录，不把输入框清空或消息回显视作成功。退款、取消或规则变化会阻止旧发货。

自动退款是独立开关。开启后，检测到需商家同意的退款申请即按平台最新状态提交，不设置金额门槛或额外审核等待。结果不明时继续核实，不盲目重复提交。

## 页面和网络

“店铺工作台”适配窗口高度，外层不再上下滚动；客服和订单各自在内嵌页面内部滚动，连接检测面板可独立滚动。打开本地编辑窗口时隐藏内嵌页面，关闭后恢复，避免遮挡。

断网恢复稳定 5 秒后，当前可见的官方页面自动刷新一次，客服连接失效时也会恢复；隐藏的订单页保留原会话，避免无必要的重新加载。已有登录、滑块验证或未发送草稿时保留页面，正在进行中的操作先等回执。短暂网络抖动不会不断重载，手动暂停后仍保持暂停。

客服答复、订单发货和售后退款分别检查连接。订单页需要验证时，正常的客服答复继续；需要订单核验的发货保留，验证完成后自动检查并续跑。售后独立读取，缺少买家编号的退款申请需等待订单详情可用。订单空闲时约每 10–12 秒扫描，临时失败逐步延长到最多 60 秒后重试；明确的订单验证约每 30 秒检查一次。界面分别显示各功能状态，运行日志记录异常和恢复。

页面仍显示验证不一定说明全部接口停用。页面提示和接口检测分别显示；平台明确要求登录、滑块或安全验证时，由本人在官方页面完成，完成后继续检查恢复。已识别的普通新功能引导、功能介绍和浏览器通知提醒可自动关闭。通知提醒优先点击官方“今天不再提示”，记住当天选择；页面加载、刷新及后续弹出时持续检查，关闭失败会退避重试，并记录提示类型与结果。

## 后台运行

点击窗口“×”默认收起到系统托盘，已有监听继续运行。双击托盘、选择“打开工作台”或再次打开快捷方式可恢复窗口；托盘菜单“退出”彻底关闭。

可启用打开软件自动监听、启动补答近七天待回复会话。启动后也扫描已有待发货订单。电脑关机、休眠、退出程序或网络未恢复时，无法继续执行平台业务。

掉线恢复或定期补答检查时，如果会话末尾是平台的等待超时提醒、商品来源提示等消息，软件会读取历史找回被遮挡的原始咨询。确认平台仍标记待回复、后续没有真实商家答复后，按当前关键词或默认答复安排补答。历史读取失败会继续重试；运行记录保留提示还原、任务恢复及实际发送回执。

## 异常掉线提醒

打开“助手设置 → 异常提醒”。电脑右下角弹窗默认开启，不需要注册推送服务；点“预览桌面弹窗”可查看效果。弹窗不抢输入焦点，助手收起到托盘时仍会显示。点“打开助手查看”恢复主窗口，点“稍后处理”只收起提示，后台继续尝试恢复。

默认在持续异常达到 **60 秒**、累计至少 **3 次检测或恢复失败**后提醒，两个条件需同时满足。可修改时间和次数，点击“保存提醒设置”。同一次异常只弹一次；恢复正常并稳定一分钟后自动收起，之后发生的新异常可再次提醒。手动暂停不报警，首次使用尚未完成登录时也不报警。客服、订单和售后的实际连接结果分别参与检测，页面上单独出现滑块但实际接口正常时不会直接当成全部掉线。已有订单异常后发生整个客服掉线，会重新升级提醒。

微信推荐使用 **Server酱Turbo**：

1. 在提醒设置中选择“普通微信 · Server酱Turbo”，点“打开服务官网”，本人用微信扫码登录。
2. 按官网要求绑定微信接收通道，在 SendKey 页面复制 **SCT 开头**的密钥。
3. 将密钥粘贴到软件的 SendKey 输入框，开启“启用手机提醒”，点“保存提醒设置”。
4. 点“发送测试提醒”，确认自己的手机确实收到，再用于正式监控。显示“推送服务已受理”仅说明服务接收了请求，不能代替手机收件确认。

[Server酱官方注册与 SendKey 说明](https://sct.ftqq.com/docs/getting-started/sendkey/)：目前免费会员每天最多 5 条，额度与接收通道要求以官网为准。Server酱³ 的 sctp 密钥用于另一款 App，本功能使用 Turbo 的 SCT 密钥。

也可选 PushPlus 微信或短信，在服务官网绑定接收方式并完成实名配置。根据 [PushPlus 官方短信说明](https://www.pushplus.plus/doc/extend/sms.html)，短信约 0.1 元/条、需要服务账户有积分，手机收到的是服务固定提示，详细异常在服务中查看。短信需自行选择和配置；软件不会自动购买积分。“恢复后再通知一次”默认关闭，开启后也会消耗服务额度或短信费用。

密钥使用 Windows 本机加密，单独保存在本机提醒配置中，不显示在设置回读数据里，也不随规则备份或规则迁移导出。提醒设置独立保存，不暂停正在进行的答复、发货或退款。通知只包含异常类型、时间及失败次数，不附带买家消息、订单、店铺名称或登录凭据。提醒事件保存在本机 phone-alerts.jsonl，便于排查漏报和推送失败。

手机通知取得服务受理回执后，同一故障不重复提交；失败会退避重试，最多 3 次，结果会显示在提醒设置中。推送服务额度不足、绑定异常或手机关闭通知时，仍需在服务侧处理。电脑完全断网时桌面提示可用，但本机无法即时向手机发消息；恢复后会补充尚未发出的故障摘要。电脑休眠、关机、程序崩溃或退出时，需要独立运行的外部心跳监测，当前本机提醒不能覆盖这些情况。

### 电脑断网时也通知（独立测试中）

正式安装包目前仍使用上面的本机提醒。新的“云端离线监护”先在独立测试版验证，确认后再发布安装包。

它让电脑每15秒向你自己账号中的 Cloudflare 服务报一次运行状态；电脑断网、休眠、程序停止报平安，或店铺连接持续异常约一分钟时，云端通过 Server酱 提醒微信。免费方案不需要购买服务器，但必须先测试当前网络能稳定访问监护地址，推送也会受服务额度和送达延迟影响。

测试版入口在“助手设置 → 异常提醒 → 云端离线监护”。填写自己部署的 HTTPS 地址与心跳密钥，再单独把 Server酱 SendKey 配置到自己账号的 Worker Secrets；软件不会自动读取或上传正式版手机密钥。监护只发送运行状态，不上传聊天、订单或登录信息。不同电脑和正式 / 测试实例应各自部署，不能用同一份心跳配置互相覆盖状态。

启用并取得云端确认后，手机故障提醒由云端负责，电脑右下角弹窗仍正常显示。同一故障的提醒被服务受理后不重复提交，恢复稳定一分钟后才把后来的故障算作新事件。手动暂停并得到云端确认后不报警；直接关闭程序、关机或休眠仍会被视为失联。维护或停用前先主动暂停，核对云端已确认，不能在断网时把未提交成功的暂停当成已完成。

## 本地数据和分发

“助手设置 → 备份与迁移”分别提供“智能答复规则”和“发货规则”的导出、导入。答复文件包含关键词、匹配方式、答复正文、欢迎语和默认答复；发货文件包含商品 / SKU 关键词、排除词、网盘正文、默认发货和统一尾缀。两个文件均不包含登录会话、订单、买家记录或自动处理开关。

淘宝助手独立开发和运行，各自保存登录会话、规则与订单状态，通过这两个文件复用内容。迁移完成后两端分别维护；修改一端不会自动改变另一端。

在对应类别选择“导入并预览”，也可读取旧的合并文字文件或第 1 / 2 版规则备份，仅提取所选类别。选错新文件类别会提示，不会导入。默认合并，按规则编号覆盖，同名但编号不同会新增；替换只移除所选类别中、文件里没有的普通规则，另一类别的正文与匹配设置保持原样。本机平台系统规则保留。展开每项可核对原内容和导入后内容，确认前取消不会修改规则。

图片需要按店铺重新配置：带图片的来源规则或被覆盖的本机图片规则，仅导入文字并停用，补齐图片、核对正文后再手动启用。欢迎语、默认答复或默认发货涉及图片时，保留该项本机文案和图片；来源平台系统规则不导入，预览列出待处理项目。其余通用文案按预览更新，发送限制和全局延迟仍使用本机设置。

确认导入前先暂停监听并等待平台操作完成。导入会在本机数据目录的 `rule-backups` 中保存原规则备份，并关闭自动监听、答复、发货和退款；核对规则后再按需开启。预览期间本机设置变化时，需要刷新预览再确认。原来的“规则备份”入口仍用于完整规则与设置备份、恢复。

升级沿用 `%APPDATA%/LinkDeliveryWorkbench`，保留已有规则、图片缓存、任务和浏览器登录会话。规则备份通过软件里的导出功能单独保存；导入规则后自动处理保持关闭。

运行记录保存发送、发货和退款的回执与重试状态。图片上传、弹窗清理、网络恢复分别有本机错误或状态日志，方便定位问题。

向普通使用者分发安装包即可；便携程序无需安装，干净源码包供开发者使用。每位使用者在自己的电脑登录并配置自己的规则，不复制本机数据目录。安装包、便携程序和源码包不包含开发者的店铺规则、登录会话、客户信息或第三方客户端文件。
